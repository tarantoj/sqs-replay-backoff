# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## Project overview

`@tarantoj/sqs-replay-backoff` is a jsii AWS CDK construct library that replays SQS messages back to a source queue with exponential backoff. It contains:

- `src/` — TypeScript CDK constructs (`SqsReplayer`, `SqsQueueWithReplay`).
- `lambda/` — the Rust replayer Lambda, cross-compiled and shipped prebuilt inside the npm package.
- `assets/lambda/bootstrap` — build artifact (not committed): the ARM64 Lambda binary consumed by `SqsReplayer`.

The Lambda is triggered by a replay queue and re-sends each message to a source queue with delay `min(maximumDelay, backoffRate * 2^attempt)`, tracking attempts via the `sqs-dlq-replay-num` message attribute, and reports a batch item failure once `maxAttempts` is exceeded.

## Tooling

- [devenv](https://devenv.sh/) manages the development environment. Enter it with `devenv shell` (provides node/npm, Rust toolchain with `aarch64-unknown-linux-gnu` target, `cargo-lambda`, `cargo-zigbuild`, `zig`).
- [projen](https://projen.io/) manages project configuration. All projen-managed files are generated from `.projenrc.ts`; **edit `.projenrc.ts` and run `npx projen`** to regenerate. Do not hand-edit generated files (files with the "Generated by projen" header, `package.json`, `.gitignore`, `.npmignore`, `.github/workflows/`, `tsconfig.json`, jest config, `API.md`).

## Bundling the Rust lambda

- `scripts/bundle-lambda.sh` cross-compiles the lambda with `cargo zigbuild --target aarch64-unknown-linux-gnu --release` and copies the binary to `assets/lambda/bootstrap`.
- The `bundle:lambda` projen task runs as a prerequisite of `build`, so every build/package embeds the freshly built binary.
- The construct resolves the asset at `join(__dirname, "..", "assets", "lambda")` (the installed package's `assets/` directory).
- `assets/` is gitignored (build artifact) but shipped in the npm tarball (`!.npmignore` handles this — see `.projenrc.ts`).

## Conventions

- jsii compatibility is required for `src/`: public APIs must be jsii-clean (no union return types, documented props, etc.).
- The construct library must stay generic — do not add deployment-specific dependencies (e.g. monitoring/observability frameworks) as runtime deps.
- Tests use [vitest](https://vitest.dev/) (`vitest.config.mts`); projen's jest integration is disabled (`jest: false`).
- Rust code: keep the three logical modules (`environment`, `backoff`, `replay`); pure logic is unit-tested in-crate; keep `main.rs` thin.
- Keep behavior aligned with the reference implementations:
    - Lambda semantics: replay with exponential backoff, `sqs-dlq-replay-num` attempt tracking, and batch item failures.
  - Construct semantics: the queue-with-replay and queue-replayer pattern (redrive chain + replayer).

## Environment variables (Lambda)

- `QUEUE_URL` (required) — queue to send replayed messages to.
- `MAX_ATTEMPTS` (default `5`) — replay attempt limit.
- `BACKOFF_RATE` (default `30`) — backoff multiplier in seconds.
- `MAXIMUM_DELAY` (default `900`, max `900`) — upper bound on the delay in seconds.
- `RUST_LOG` (default `info`) — tracing filter.

## Releases

- The GitHub release workflow cross-compiles the Rust lambda before packaging (rust + zig + `cargo-zigbuild` are installed via `workflowBootstrapSteps`).
- Publishing is configured but dormant until a `NPM_TOKEN` secret is added to the repository.
